# RCMDT 项目研究说明

副标题：面向公交走廊数字孪生的观测语义审计与鲁棒校准

## 这是什么项目

这个项目对应我正在投稿 2026 IEEE SMC 的一篇会议论文，论文题目是：

**Operator-Aware Auditing and Robust Calibration of Bus-Corridor Digital Twins Using Bayesian Optimization and Iterative Ensemble Smoothing**

如果只用一句话概括，这个项目想解决的不是“如何把仿真调得更像真实数据”，而是一个更基础、也更容易被忽视的问题：

**当公交运行数据里的“观测量”本身混入了调度保持、恢复班次、终点站停靠等运营语义时，数字孪生会被错误地校准。**

在很多交通仿真或数字孪生工作里，研究者会直接拿 door-to-door 的站间旅行时间去做校准。但对公交系统来说，这类观测并不总是纯粹反映交通状态。它常常同时包含了交通拥堵、站点上下客、车辆等待发车、holding、layover 等多种机制。这样一来，模型会把本来属于“运营控制”的慢速长尾，误解释成“交通状态”或者“车辆行为参数”的问题。参数能被调得更贴近数据，但解释会偏，迁移也会差。

我做这个项目，就是想把这件事拆开。

## 研究问题

这个项目围绕三个相互关联的问题展开。

1. 公交数字孪生的校准目标，究竟应该直接使用原始的站间旅行时间，还是应该先审计观测语义？
2. 如果观测中同时混有 stop-level 行为和 corridor-level 背景交通状态，参数辨识会不会出现耦合和漂移？
3. 当研究目标从“均值误差最小”转向“可靠性与分布对齐”时，校准和验证应该怎样分开设计？

我的判断是，公交场景下最难的部分并不是优化器本身，而是**观测口径是否干净、校准对象是否分层、验证指标是否真的对应可靠性**。

## 核心想法

这个项目的核心想法有两步。

第一步，不把观测当作天然正确的输入，而把 observation operator 当作研究对象本身。也就是说，先审计“我们到底在测什么”，再谈校准。

第二步，把校准拆成两个层次：

- L1 负责 stop-related 参数反演，处理微观行为层的问题。
- L2 负责 corridor background state reconciliation，处理宏观交通状态的问题。

这样做的原因很直接。如果把所有误差都塞给一组参数，模型最后会学到一个“平均上看着不错，但物理解释混乱”的结果。尤其在公交系统里，holding 和 layover 这类非交通机制很容易把参数带偏。

## 方法链路

整个框架在仓库里叫 **RCMDT: Robust Calibration of Mobility Digital Twins**。它是一个两层闭环。

### 1. 观测语义审计

我先从 door-to-door 观测里识别出那些看起来像拥堵、但实际上更像运营语义污染的样本。仓库里把这一步实现为 Rule C：

- 当 `T > 325s`
- 且 `v_eff < 5 km/h`
- 且 link 距离处于短距离约束内

这类样本会被标记为 ghost regime，而不是直接送进校准目标里。

这个规则的重点不是“绝对完美分类”，而是让观测口径变得可审计、可复现、可解释。仓库里对应的主图是：

- `plots/P14_ghost_audit.png`
- `plots/P14_robustness_cdf.png`

### 2. L1：代理模型辅助的贝叶斯优化

L1 负责 stop-level 参数搜索。这里我没有直接做大规模暴力仿真，而是用高斯过程代理模型近似目标函数，再用 Expected Improvement 做采样。

在代码实现里：

- 代理模型见 `src/calibration/surrogate.py`
- 目标函数见 `src/calibration/objective.py`

L1 的目标也不是单一 RMSE，而是一个更偏鲁棒性的复合损失 `JL1`。它把三类信息放在一起：

- 平均拟合误差
- 误差离散程度
- 尾部风险

对应的形式是：

`JL1 = RMSE + α(MAE + λ·std(|e|)) + β·Q0.9(|e|)`

这意味着优化器不会只追求“均值好看”，而是会主动压制长尾和不稳定误差。

### 3. L2：基于 IES 的走廊状态同化

L2 负责 corridor-level 的背景状态更新。统一实验协议里，我把状态向量定义成三维：

- `capacityFactor`
- `minGap`
- `impatience`

观测向量定义成 M11 走廊的 11 维 moving-only 平均速度。当前仓库的统一 L2 配置写在 `config/calibration/l2_protocol_config.py`，其中主要设置是：

- `x ∈ R^3`
- `y ∈ R^11`
- `Ne = 10`
- `K = 3`
- `β = 0.3`

这个层次的目标不是重新改 stop 参数，而是承认“背景交通状态会漂移”，然后用 IES 在固定时间窗内做状态协调。

### 4. 校准与验证分离

这是我比较在意的一点。很多工作会一边调参，一边报验证指标，最后很难判断性能到底来自模型能力，还是来自反复贴合验证集。

在这个项目里，校准和验证被有意拆开：

- 校准阶段最小化标量损失
- 验证阶段只报告分布级证据，不再回调优化器

验证主要看两类指标：

- K-S distance
- worst-window stress test

这更接近“可靠性”语境下的评价，而不只是平均误差语境。

## 目前形成的技术贡献

如果把这个项目当成一份小型研究工作来概括，我认为它的贡献主要在下面四点。

### 1. 把 observation operator 从默认前处理，提升成了显式研究对象

这不是简单做数据清洗。更准确地说，是在公交数字孪生场景里讨论“什么样的观测才应该进入校准闭环”。这一步直接关系到后续参数是否可辨识。

### 2. 用两层结构拆开了 stop behavior 和 corridor regime

L1 负责行为参数，L2 负责背景状态。这样做减少了“用微观参数去硬拟合宏观 regime 错误”的风险，也让结果更容易解释。

### 3. 把鲁棒性目标写进了优化目标，而不是只在结果分析里补一句

JL1 不是普通 RMSE，它显式约束了离散程度和尾部风险。这一点和项目后面强调的分布验证是连起来的，不是两套互相独立的叙述。

### 4. 把验证重心放在分布对齐和压力测试

这个项目更关心“模型是否能在跨日迁移和困难窗口下保持解释力”，而不是某一个平均指标能不能再低一点。

## 实验设置与目前结果

项目使用的是基于 SUMO 的香港公交走廊数字孪生场景，论文和仓库里的核心分析围绕两条公交线路展开。

从目前论文稿和仓库中已经固定下来的结果看，有几组结论比较关键。

### 1. 语义对齐前后，分布差异明显变化

在当前结果里，未经审计的 raw operator 与仿真之间存在显著错位，K-S 距离大约在 `0.54` 量级。经过 Rule C 审计后，clean 分布与仿真之间的 K-S 距离下降到 `0.2618` 左右。

这说明问题不只是“模型还没调好”，而是原始观测口径本身混入了不该由交通状态解释的内容。

### 2. 语义错配时，IES 会被带偏

论文稿里有一组我认为很关键的 ablation。

- 在错误语义的 G1 设置下，IES 不但没有改善，K-S 还从 `0.325` 变成了 `0.360`。
- 在正确语义的 G2 设置下，IES 把 K-S 从 `0.325` 降到 `0.262`，改善约 `19.4%`。

这组结果支持了一个很直接的结论：**状态同化本身不是万能的，前提是观测语义要对。**

### 3. 外层 BO 比随机采样更有效

在当前论文结果里，贝叶斯优化相对 LHS baseline 把最优 combined objective 从 `161.70` 改进到 `148.20`，增益约 `8.35%`。

这说明代理模型在这个高成本仿真校准问题里是有实际价值的，不只是方法堆叠。

### 4. 小规模校准集可以迁移到更大的验证集

当前论文稿里，L2 校准使用的是 `n = 11` 的核心观测向量，验证则扩展到了 `n = 52` 的 clean links。即使在这种设置下，模型仍然表现出可接受的分布泛化能力。这一点对“数字孪生是否能离开局部样本继续工作”是重要的。

## 我更希望导师看到的研究价值

如果把这个项目放在更大的科研语境里，我希望它能体现三件事。

第一，我不是把 SUMO 当成一个黑箱仿真器来调参数，而是在讨论**数字孪生里的观测、状态、参数和验证之间应该怎样被正确组织**。

第二，这个项目虽然落在公交场景，但核心问题具有更一般的意义：**当观测量混有不同机制的语义时，数据同化和系统辨识会怎么失真，以及如何通过可审计的 observation operator 把它纠正回来。**

第三，这项工作把交通工程、数据同化和鲁棒验证连在了一起。它既有模型层的设计，也有实验层的证据链，不是纯工程堆栈。

## 当前局限

这个项目还有几个我认为必须坦白写出来的局限。

### 1. Rule C 仍然是规则型审计，不是学习型语义识别

它的优点是清楚、稳定、可复现，缺点是表达能力有限。未来如果引入更细粒度的运营日志，完全可以把它推进到概率化或因果化的 regime inference。

### 2. L2 的状态维度目前比较克制

当前统一协议只用了三维背景状态，目的是先保证识别稳定和实验口径一致。更复杂的状态设计还没有完全展开。

### 3. 当前验证仍以离线实验为主

现在的贡献重点是离线校准、跨日迁移和短时压力测试。在线更新、流式同化、以及显式建模 holding/schedule recovery，还没有在这个版本里完成。

### 4. 开源仓库无法完整附带真实原始数据

因为数据合规原因，仓库里保留了可复现实验脚本、图和 synthetic fixtures，但不是所有真实输入都能公开分发。这也是为什么我专门保留了 `DATA.md` 来说明数据与合规边界。


```bash
python scripts/smoke/p14_smoke.py
```

## 如果要完整运行研究流程

完整研究流程需要本地准备好：

- Python 3.11+
- SUMO 1.20.0
- 项目依赖 `requirements.txt`
- 本地可访问的 processed inputs

安装依赖：

```bash
pip install -r requirements.txt
```

运行全流程时，常用入口包括：

## 适合向导师怎么介绍这个项目

如果我向导师做 2 到 3 分钟介绍，我会这样概括：

> 这是一个面向公交走廊数字孪生的鲁棒校准项目。它的重点不是继续做“仿真拟合真实数据”的常规工作，而是先处理观测语义污染导致的辨识偏差问题。我把 door-to-door 观测中的运营语义和交通语义分开，再用两层闭环把 stop-level 行为参数校准和 corridor-level 状态同化拆开。最后不用均值误差作为唯一标准，而是用 K-S 距离和 worst-window stress test 去看分布级可靠性。现在这套方法已经写成一篇在投的 IEEE SMC 2026 论文，也在这个仓库里实现了对应的实验链路。
